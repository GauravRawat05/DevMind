1. Project Overview
DevMind is a production-grade, AI-powered Multi-Agent Code Intelligence Platform. It enables developers to connect any GitHub repository and instantly get automated code documentation, intelligent code review, natural language Q&amp;A about the codebase, and complexity analytics — all powered by specialized LangGraph agents running in parallel, with results streamed live to the frontend.

This project is built as a portfolio-grade system to demonstrate full-stack + AI engineering skills across the complete modern Python developer stack.

1.1 Problem Statement
Developers waste significant time onboarding to new codebases, writing documentation, and performing manual code reviews. DevMind automates these cognitive tasks using specialized AI agents that collaborate to provide instant, actionable intelligence about any codebase.

1.2 Target Users
Developers onboarding to new or legacy codebases
Engineering teams needing automated documentation and review
Open-source maintainers managing large repositories

1.3 Core Value Proposition
4 specialized agents run in parallel — not sequential — reducing total analysis time
Real-time streaming output via WebSockets — no waiting for a full response
Production-deployed on AWS EC2 with Docker, S3 for file storage, GitHub Actions for CI/CD

3. System Architecture

3.1 High-Level Architecture
The system follows a microservices-inspired architecture with a clear separation between the user-facing Next.js frontend, the FastAPI backend orchestration layer, and the specialized agent subsystems.

Request Flow:
User submits GitHub repo URL via Next.js frontend
Next.js sends POST request to FastAPI /analyze endpoint
FastAPI validates request, stores job in PostgreSQL, pushes task to Celery via Redis
Celery worker picks up task and triggers LangGraph multi-agent pipeline
4 agents run in parallel: Doc Agent, Review Agent, Q&amp;A Agent, Analytics Agent
Each agent streams partial results back through WebSocket connection to frontend
Final results persisted to PostgreSQL + MongoDB; files stored in AWS S3
GitHub Actions runs tests and auto-deploys to AWS EC2 on push to main

3.2 Agent Architecture (LangGraph)
Each agent is a standalone LangGraph node with its own system prompt, tool bindings, and output schema. The orchestrator node manages state and routes results back to the WebSocket layer.

7. Agent Design Details

7.1 Doc Agent
Input: Raw source files fetched from GitHub API
Process: LangChain prompt chain reads each file, extracts function signatures, class definitions, and module purposes
Output: Structured README.md with Project Overview, Installation, API Reference sections
Storage: Final .md file uploaded to AWS S3; S3 key saved in jobs table

7.2 Review Agent
Input: Parsed source files + file-level metrics from Analytics Agent
Process: LangChain reviews each file against a rule set (error handling, security, naming, complexity)
Output: JSON array of issues: { file, line, severity, message, suggestion }
scikit-learn: Used for anomaly detection on complexity scores to flag outlier files

7.3 Q&amp;A Agent (RAG-powered)
Input: User natural language query + ChromaDB vector store of the repo
Process: Query embedded via Hugging Face CodeBERT → top-k chunks retrieved from ChromaDB → Groq/Llama-3 generates answer with context
Output: Natural language answer with source file + line references
Memory: Full Q&amp;A history stored in MongoDB qa_history collection

7.4 Analytics Agent
Input: All source files parsed to Abstract Syntax Tree (AST) via Python ast module
NumPy: Matrix operations for dependency graph analysis
Pandas: DataFrame construction for per-file metrics (LOC, complexity, function count)
scikit-learn: KMeans clustering to group files by complexity tier
Output: Dashboard-ready JSON: { file_metrics[], complexity_distribution, top_issues[], tech_debt_score }
